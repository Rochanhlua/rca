- **Implemented:** native codegen for `map_set` and `map_has` — the map layout is `[len][tag][key][value]…` (Int/Float/Str/Bool key tags), with linear-scan lookup. `map_set` updates an existing key in place or allocates a new buffer on insert; `map_has` returns a `Bool`. Both match the VM, including same-key updates and Int keys. The previous buffer on insert is not freed (tracked in `docs/memory-model.md` §3a).

- **Implemented:** native codegen for `map_get` and `print(map)` — `map_get` scans by key tag plus comparison (strcmp/fcmp/icmp) and returns the stored value; a missing key prints `runtime error: map_get(): key not found` and exits 1 (the VM adds a `LINE:COL` prefix; span-aware errors are a separate milestone). `print(map)` emits `Map(size=N)`. Together with `map_new`, `map_len`, `map_set`, and `map_has` this completes the native Map feature set. `map_get` currently tags its result as `Int`, matching the checker's `Type::Unknown` for map values; non-Int values would be mis-printed until value-type tracking lands.

- **Implemented:** map value-type tracking for native `map_get` — lowering records the type of each `m = map_set(m, \"key\", value)` assignment (and clears it on any other rebinding), so `map_get(m, \"key\")` can be emitted as `Instruction::MapGet(Type)`. Codegen pushes the matching `StackType`, and `Print`/arithmetic/comparison use the correct path; `examples/map_demo.rca` now matches the VM (`RCA` instead of a heap address). Non-literal keys fall back to `Int`.

- **Implemented:** native codegen for the math builtins `abs`, `pow`, `floor`, `ceil`, and `round` — `abs` is branchless for Int and a sign-bit mask for Float; `pow`/`floor`/`ceil`/`round` call libm (with `-lm` added to the link line in both build paths). Int arguments convert to F64 for the libm calls; `pow` converts back to Int when both operands were Int. Float results use the existing fixed 3-decimal print format (the VM uses shortest form; tracked below). `examples/math_demo.rca` runs natively.
- **Planned:** exact saturation and domain-error parity between native `pow` and the VM for edge cases (0^0, negative bases with fractional exponents), and float shortest-representation parity with the VM.
- **Implemented:** native codegen for `try`/`catch`/`throw` — the lowering already emitted `PushHandler`/`PopHandler`/`Throw`; this adds the runtime side. Codegen keeps a small stack of saved `sp` values, seals the catch block the first time it is entered, and rewrites every runtime error site (division by zero, integer overflow, list index out of bounds for reads and stores, `map_get` miss, `Neg` overflow) to jump to the active handler with a short message instead of exiting. Catch output matches the VM (`caught: division by zero` etc.); top-level errors keep the `runtime error: ...` prefix and exit 1. `examples/try_demo.rca` now runs natively.
- **Planned:** source-span-aware error messages (`LINE:COL:` prefix, still VM-only), and `try`/`catch` across function boundaries in native codegen.
